## 活詞彙表草案的使用規則

1. **raw tag 首先代表讀者可沿著走下去的閱讀關係。** 搜尋命中只是次要價值，不能用標題或摘要的字串碰巧命中來冒充關係。[brainstorm-2026-08-30.md:3-5](file:///Users/linhancheng/Desktop/projects/gggodlin-blog/.scratch/tag-governance/brainstorm-2026-08-30.md#L3-L5)
2. **允許主題、文章角度與專名混用。** 每個 tag 都要能回答兩題：「未來是否可能再放文章進來？」以及「讀者是否可能沿著它繼續讀？」混合維度本身不是問題，沒有意思與邊界才是問題。[vocabulary-audit.md:54-62](file:///Users/linhancheng/Desktop/projects/gggodlin-blog/.scratch/tag-governance/vocabulary-audit.md#L54-L62)
3. **singleton 不因只出現一次而刪除。** 專名、窄主題與文章角度都可以先作系列種子；若日後沒有串讀價值，再依內容與讀者證據重評，不按次數大掃除。[brainstorm-2026-08-30.md:7-13](file:///Users/linhancheng/Desktop/projects/gggodlin-blog/.scratch/tag-governance/brainstorm-2026-08-30.md#L7-L13)
4. **活詞彙表不是封閉白名單。** 新 tag 可以加入，但發布前要明確確認並登記標準寫法、顯示名稱、維度、意思、邊界與已知舊寫法；未確認前不能無聲混入。[brainstorm-2026-08-30.md:5-12](file:///Users/linhancheng/Desktop/projects/gggodlin-blog/.scratch/tag-governance/brainstorm-2026-08-30.md#L5-L12)
5. **同概念只保留一個標準資料 ID。** 一般資料 ID 採小寫 kebab-case 與單數；專名的官方大小寫放顯示名稱。`Claude Code`／`claude-code`、`MCP`／`mcp`、單複數家族都依這條收斂，但前提是資料 ID 與顯示名稱分離。[vocabulary-audit.md:19-41](file:///Users/linhancheng/Desktop/projects/gggodlin-blog/.scratch/tag-governance/vocabulary-audit.md#L19-L41)
6. **近義關係要明列，不能靠 substring。** `testing` 是否包含 `ai-testing`、`security` 是否屬於品質入口，必須由詞彙表或 topic alias 明文表達。[vocabulary-audit.md:401-424](file:///Users/linhancheng/Desktop/projects/gggodlin-blog/.scratch/tag-governance/vocabulary-audit.md#L401-L424)
7. **工具生命週期分三條路。** `tooling` 是具名工具接線與限制；`tool-evaluation` 是引入前的契合度與紙上上限；`tool-adoption` 是安裝、試用、留用、退役或抽件。三者可以同篇共存，但不能互當 alias。[vocabulary-audit.md:49-52](file:///Users/linhancheng/Desktop/projects/gggodlin-blog/.scratch/tag-governance/vocabulary-audit.md#L49-L52)
8. **文章角度與執行流程分開。** `methodology` 是可重複的判準或量尺；`retrospective` 是用使用後證據回看舊決定；`workflow` 要有明確階段、編排或可重跑入口；`ai-workflow` 只收 AI 直接參與資料或決策流程的窄集合。[vocabulary-audit.md:47-51](file:///Users/linhancheng/Desktop/projects/gggodlin-blog/.scratch/tag-governance/vocabulary-audit.md#L47-L51) [vocabulary-audit.md:222-230](file:///Users/linhancheng/Desktop/projects/gggodlin-blog/.scratch/tag-governance/vocabulary-audit.md#L222-L230)
9. **不設定固定 tag 數量。** 每個 tag 都要有內容證據；沒有證據就不加，有多個獨立閱讀維度就可並存。現有 2–3 類命中多數合理，數量本身不是失真證據。[topic-mapping-audit.md:144-185](file:///Users/linhancheng/Desktop/projects/gggodlin-blog/.scratch/tag-governance/topic-mapping-audit.md#L144-L185)
