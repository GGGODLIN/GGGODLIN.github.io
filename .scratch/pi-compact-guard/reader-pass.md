# Phase 5.5 讀者對抗 pass — compact-guard（v5-pi-gemini）

扮演讀者：使用 AI 工具工作的工程師，知道 context 有上限、長對話可能被摘要，但完全沒看過作者的內部工具、hook 接線與試用帳本。

## 整體可讀性

口語順暢、比喻（買保險／這張保單）前後一致、「實驗室跑得過不算數」這段的節奏與誠實度好，事故故事抓人。但機制段與數據段密集出現未定義的內部語彙與懸空數字（`KEEP`、`觀察期`、`判決`、`封存觀察窗`、`被取代事件`、`四種介面`、`八份`），讀者只能在「大概懂」的層次硬著頭皮往下走，且走完仍無法回答「這套保險我能複製到我的工具上嗎」。

## 最大的三個理解斷點

1. **機制裝在哪個產品上（GPT ／ Claude Code ／ Codex 的三角關係）**：事故發生在 GPT，hook 卻從未指明宿主，GPT 是否支援這些 hook、是不是「四種介面」之一，全文未答。這是根本定位問題，其餘斷點都從它連出來。
2. **恢復的觸發時序（SessionStart vs 壓縮發生在 session 中間）**：壓縮完的當下誰負責注入？讀者必須自行假設「compact = session 重啟」才能把 L23–25 的流程圖補完，但文章沒給這個假設。
3. **內部試用語彙當成通用詞用（KEEP／觀察期／判決／封存／被取代事件）**：這些是作者試用帳本的專名，卻被當成讀者已知的詞，每遇到一個就要猜一次，猜完還不確定對不對。
