借一次判斷：Advisor 的方法論

不換掉整個 session，只把這一題交給另一顆腦袋。

有時我只是對這一次思考不滿意。
但整個 session 換成強模型，後續工作也一起換了。
能不能只把這次判斷交出去？

接續主篇

這篇從模型分工拆出來。主篇的分界一句話：

派工
交出一件有範圍、有驗收條件的工作。
顧問
借對 main 某個判斷的第二意見。沒有交付物，只有意見。

這篇只講方法，不講我怎麼把它接起來的實作細節。

02官方也有

Claude Code 內建了 advisor，差別不只是誰按下去

先公平講官方版。它讓 Claude 在關鍵時刻諮詢另一顆、通常更強的模型。

  • Claude 決定何時問，常見時機是選定做法前、同一個錯誤反覆出現時、宣告完成前。你也可以在 prompt 裡叫它問。

  • 顧問一律收到完整對話，包含每次 tool 呼叫與結果。

  • 顧問是 Claude 自家模型，由你選哪一顆。

  • 目前是 experimental，要走 Anthropic 官方後端，訂閱與 API 計費帳號都能用；Bedrock、Google Cloud 等雲端平台不支援。

我的做法差在三件事

材料能不能挑

官方固定送完整對話。我可以只送任務與事實，拿掉自己的結論（第 4 章）。

能不能跨廠商

官方顧問是 Claude 模型。我也找其他廠商的模型，換一個訓練背景不同的視角。

回來怎麼處理

我要求逐條裁決（第 6 章）。官方文件沒描述這一步，這不代表官方沒有。

不說誰比較好。官方版省事、時機自動；我的版本多了控制，也多了手續。

觸發時機：我試過自動提醒

我曾經加過「該找顧問了」的自動提醒。結果是每次都看到，也每次都略過，最後停用。

所以我目前實際會用的時機，是自己覺得「這次不對勁」的那一刻。另一個顧慮是：讓正在做事的模型自己評估「我需不需要求救」，本身也是一題不穩的判斷。

這只說明提醒沒被我採用，不證明人的直覺比較準，也不是對官方自動觸發的評測。人往往在不知道自己判錯時，最需要第二意見。

官方說明：Claude Code advisor 文件，查證日 2026-10-01。官方標 experimental，行為與可用性可能變動。

03選顧問

先看它能不能自己查證，再看它擅不擅長

「哪顆比較聰明」很難證明。「它能不能自己去讀檔、跑指令核對」是確定的事實，決定它能自己補哪些證據。你把證據送齊，只讀文字的顧問也能審實作；有工具，也不代表它判斷得對。

顧問能做的事比較適合
能自己讀檔、跑唯讀指令實作層：指令對不對、程式碼和宣稱是否一致、實驗設計成不成立
只能讀你送的文字思路與框架：論證有沒有跳步、問題設定對不對

同一顆也算第二意見，但盲區可能相同

官方文件就把同型號搭配列為選項，例如 Sonnet 配 Sonnet 是「lower-cost second opinion」。我偏好換一顆模型，增加視角差異；用同一顆時，不要假定它的盲區和 main 不同。換廠商也不保證錯誤互相獨立。

不做排名

這頁不比較模型或產品。顧問是互補，不是更強：價值來自換一個視角，不是換一顆更好的腦袋。

04材料

給什麼材料，決定你拿到哪種意見

把整段對話丟給顧問，看起來最完整。但完整不等於獨立。

你要的給顧問什麼刻意不給什麼
挑我的錯原始問題、我的結論、我排除過的選項，三樣分開標—
獨立想一遍（盲審）原始任務、查得到的事實、硬限制我的結論、排除項與理由，連暗示都不留
問題卡在前後脈絡對話原文，機械抽取我寫的摘要

為什麼不讓 main 自己寫摘要：摘要會帶著 main 的視角，顧問讀到的等於再看一次原本的思路。

案例：盲審是被顧問點出來的

設計自己的 advisor 用法時，我只想到兩個選項：給顧問摘要，或給完整對話。顧問的回覆：

我在兩個選項裡挑，顧問指出我根本沒看到第三個。後來加入盲審，也把顧問意見逐條裁決納入流程。

從這次帶走

  1. 要顧問挑錯，和要顧問獨立想一遍，是不同問題。
  2. 給更多脈絡，不等於拿到更獨立的判斷。

一次歷史事件，不是使用頻率統計，也不外推成固定效果。

05陷阱

prompt 裡沒寫結論，顧問就真的沒看到嗎

一次刻意的盲審，我逐字檢查過 prompt，沒有任何結論。但那條傳送路徑會自動讓顧問讀到整段對話紀錄。顧問的回答，直接引用了我先前說過的話。

意見還是有用：它照樣反駁了我的核心推論。但那是讀過我論證之後的意見，不是獨立的第二意見，採信時的分量不同。

怎麼防

  1. 先弄清楚每條管道會自動附上什麼。
  2. 真的要盲審，就選只送 prompt 內容的管道。
  3. 事後回頭確認顧問讀到什麼；讀過對話就照實標明。

2026-09-17 一次實際諮詢。只講現象與教訓，不點名工具。

06意見回來之後

顧問給幾條，就裁決幾條

顧問的意見裁決依據
一句話濃縮，不改原意接受具體要做什麼
認為意見錯反證
可能對，但這次不採納取捨理由：超出範圍、成本不值得、目前不優先
事實還不確定標「待確認」，寫下怎麼驗；驗不了就照實留著，不硬裁成對或錯

  • 說它錯，要附反證。「不適用」「我不同意」不算，那是換句話說的忽略。

  • 不採納，要講出取捨。「這次不改」是合法決定，但理由要寫得出來，而且不等於它錯了。

  • 不要只挑好改的接受。質疑整體方向的那幾條最貴，也最容易被跳過。

  • 未知就留未知。不要為了收尾，把查不清楚的事裁成對或錯。

為什麼不能省

少了這一步，顧問就成了「昂貴但不具約束力的評論產生器」。這句是一次顧問審查我的流程時講的。

意見不具強制力，但不代表可以不回應。每一條都要有明講過的去向：做、說它錯、這次不做，或待確認。

衝突時

不預設誰對。顧問可能看到盲區，也可能因為缺脈絡而誤判。把分歧點講清楚，交給人判斷。

07收尾

下次卡住時，先問自己三題

依現況誠實選：1 是還沒這樣想過，5 是已成為習慣。這只量熟悉度，不量適不適合你手上的工作。

卡住時，我是換整個 session 的模型，還是只借一次判斷？

找顧問前，我想清楚了要它挑錯，還是要它獨立想一遍嗎？

顧問意見回來，我有逐條決定，還是讀完就算了？

三題都選完後，這裡會標出你最不熟的一項，當作起點的建議。

顧問的價值是換一個視角，不是換一顆更強的腦袋。
而那個視角，取決於你讓它看到什麼。
