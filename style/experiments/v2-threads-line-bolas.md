## 句型模式（高度可複製）

### Long-form 模板（threads-main 驗證多次）

#### 1. 省流排序 + 分項心得
```
省流：A >> B >= C > D > E
分項心得：
1. A：能力相當於 X，講白話就是 Y
   缺點：<擬人化負評>
   適合使用場景：<列場景>
2. B：...
```
來源：[threads-main #4-5 中國模型評比]

#### 2. 條列回顧（時間軸 / 題型列表）
```
標題 + 引入句（最近 X / 剛好看到 Y）
Day0: ...
Day3: ...
（或）
1. <類型>：<描述> + <個人經驗>
2. ...
隨手小記，有機會再寫成一篇 medium
```
來源：[threads-main #16 台積面試 / #17 前端 live coding]

#### 3. 自問自答
```
問題篇：「有人知道 X 嗎 / 好奇 X 🤔」
答題篇：「這邊自問自答」 + 實測結果 + 「供大家參考」
```
來源：[threads-main #9-10 m5 MacBook]

#### 4. 場景 + 感悟（短打）
```
場景描述（具體動作序列）
個人感悟（甚至 / 沒想到 / 驚覺）
```
來源：[threads-main #15 ADHD、#7 猛健樂]

## 文章長度 / 結構

| 類型 | 字數區間 | 結構特徵 |
|---|---|---|
| 短哲學 / 觀察 | 1-50 字 | 單句，無結構，threads 短打 |
| 中等敘事 | 100-300 字 | 有 lead + body，threads main 一般貼 |
| 長條列評比 | 300-600 字（拆 1/2, 2/2） | 省流 + 分項心得，已驗證可拆 series |
| blog 舒適區 | **800-1,500 字** | 完整 lead / body / takeaway，含小標 |
| 超過 1,500 字 | 拆 series | 不硬撐到 3,000+，違反「省流」精神 |

LINE 驗證：技術深度討論（thread 數十條）顯示有能力展開 1,500 字等級的分析，但自發寫作節奏偏短打收尾。

## LINE 層貢獻 vs 污染分界

### LINE 真正補強 threads 的信號

| 補強項目 | LINE 例子 | 為什麼有效 |
|---|---|---|
| **高頻技術詞彙驗證**：某些詞是真實高頻非孤證 | 「SDD」「skill」「cc」「vibe coding」「claude.md」「MEMORY.md」在 LINE 出現數十次 | 確認這些詞在真實工作用語中穩定存在，非 threads 表演 |
| **量化習慣跨平台一致**：非只在公開場合量化 | 「26.25x pro」「35B-A3B 常駐 20GB」「每 21 天刷兩單 2400 台幣」 | LINE 私聊也帶具體數字，不是公開表演行為 |
| **failure-as-content 是真實性格**：不只在公開貼文說 | 「感覺我去年底訂的三千多 gemini pro 只爽了一個月，價值 600 吧」/ 入職當天設備被收回 | LINE 私聊也坦然說錯誤決策、倒楣事，不是 PR 操作 |
| **雞湯反高潮是跨平台語感** | 「能力這種東西，你可以用不上，但你不能沒有」/ 「大道至簡」 | 私聊也有，確認是個人慣用收尾而非公開貼文表演 |
| **工具擬人化口吻跨平台**  | 「gemini…是誰」/ 「給爸媽用 gemini 這種東西很不孝欸」/ 「不孝有三，給 gemini 為大」 | LINE 擬人化力度和 threads 一致 |

### LINE 私聊語域——不能搬進 blog 的部分

| 類型 | LINE 例子 | 為什麼不搬 | 安全度 |
|---|---|---|---|
| 政治強度 | 「果然清大就是中共同路校 有 85% 都是中共同路人」/ DPP 網軍分析 / 個別政治人物點名（卓榮泰 / 花蓮王） | 帶具體人名的政治攻奸，blog 讀者範圍廣 | `[群內限定]禁搬` |
| 髒話密度 | 「靠北」「幹」「操」連發，每頁 5-10 個 | 口語量比 threads 高 5-10 倍，blog 中一兩個可以，但不按此密度 | `語域外溢風險（密度）` |
| 人身評論 | 「底層之所以是底層」/ 「政治腦真的很可悲」/ 「這種爛人行為」 | 指向特定族群，blog 無特定討論對象的情況下出現很刺 | `語域外溢風險（對象）` |
| 性僻自揭 / 內圈梗 | 群內特定人暱稱、梗（如「海哥」梗）、9527 密碼事件 | 外部讀者完全無脈絡 | `[群內限定]禁搬` |
| 遊戲廢話（楓之谷） | 大量楓之谷道具交易細節 | blog 不以遊戲為主題時完全跑題 | `語域外溢風險（跑題）` |
| 日常瑣碎 | 「今天又發現住信義區的優點，尾牙高機率辦在家附近」 | 純生活流水帳，沒有觀點核心，不適合直接搬 | `語域外溢風險（無觀點）` |

**總結**：LINE 是語彙庫 + 性格驗證器，不是 blog 內容素材庫。

## Bolas 借鑑層融入點

### 採用的手法

| 借鑑手法 | 如何融入 | 和 @gggodlin 原聲相容性 |
|---|---|---|
| **「先描述失敗，再給方向」結構** | ai-frontend 整篇以「還沒答案」收尾的誠實框架，與 failure-as-content 精神完全吻合。@gggodlin 已有此傾向（DeepSeek 翻車、gemini 訂閱浪費），可強化此段落比例 | 高度相容 |
| **認知轉折句式**（「我原本以為 X，後來才發現 Y」） | 「年初的時候中國模型都撐不起 agent 的使用場景，沒想到才到年中 ⋯⋯」已有原生案例。可在技術評比段落刻意使用，增加論點說服力 | 相容，@gggodlin 有自然原型 |
| **「AI 邊界確立」段落** | 明確指出工具做不到什麼，補充完整度。@gggodlin 評工具時偏強調缺點（「很容易爆衝」），Bolas 的框架讓這更有系統感 | 相容，加分項 |
| **具體場景做開場錨** | Bolas 的「觀察同事 / 翻出舊 GitHub 專案」開場，vs @gggodlin 的「最近 X / 前兩天 Y」，本質類似——找一個具體錨點。可作為 lead 變化，不是替換 | 相容，是 @gggodlin 已有習慣的延伸 |

| Bolas 手法 | 不採用原因 |
|---|---|
| **blockquote 作為感悟容器** | @gggodlin 無此節奏元素，加進去讀起來像換人寫 |
| **教科書收尾語**（「祝大家有很好的開發體驗」） | 淡化直球語感，像 LinkedIn 文 |
| **問句小標**（「你在用 AI 改程式碼，還是完成任務？」） | @gggodlin 的語氣是「講給自己聽、你要聽就來聽」，不對讀者說話 |
| **步驟型教學慣性**（所有主張拆步驟 + 粗體） | 適合教學文，@gggodlin 是評論 + 紀錄，不是課程講義 |
| **主題集中單一 topic** | Bolas 10 篇全 AI 協作，@gggodlin 跨 topic 是品牌特色 |
| **無強情緒詞** | 若學 Bolas 語調「文雅化」，移除「爛咖/就這/幹」，整篇個性 fingerprint 消失 |

## Anti-pattern（不要這樣寫）

- **LLM 廢開場**：「在這個 AI 快速演進的時代⋯⋯」
- **教科書語氣**：「綜上所述」「值得注意的是」「不僅⋯⋯而且⋯⋯」「然而⋯⋯」
- **過度修飾**：「驚人地」「令人印象深刻」「優雅地」「極為強大」「顯著提升」
- **客觀化第三人稱**：「在使用者經驗中發現」「本文將探討」「筆者認為」
- **文件式邀請**：「請參考」「歡迎指教」「希望本文對您有所幫助」
- **全段 emoji** 像 LinkedIn
- **用「我們」當主詞**（除非真有對話對象）
- **PR 術語**：「個人化」「賦能」「賦予」「打造」「閉環」「玩法」
- **工具 emoji 條列**：✅ ❌ ⚠️ 當 marker
- **偽蘇格拉底**：「你可能會問：那 X 怎麼辦？」
- **模糊時間 / 金額**：「花了幾個小時」→ 要說「1.5 小時」；「很便宜」→ 要說「25 折、兩鎂」
- **晶晶體**（三個以上應翻沒翻的英文形容詞塞在一句中文裡）
- **「不是 X，是 Y」對偶排比**：GPT 招牌；忌「不是 A，是 B / 而是 B」「真正的 X 不是…是…」工整對偶，尤忌一篇 ≥2 次同構（讀者秒認 AI tell）。判斷直接講（「就是…而已，差在…」「X？廢話」），對比靠語氣不靠排比
- **破折號（——）每篇上限 1-2，預設不用**（PR-016/021）：人類技術寫作極少用破折號，連續拿「——」當轉折或插入是 AI 節奏 tell（code-search-adoption Phase 2 一篇冒 25 個、上線收到 2）。預設改用句號斷句、冒號帶出、逗號或括號插入；標題一律不用破折號。寫完 grep `——` 計數，超過 2 就重整標點
- **AI 儀式性過渡語**：「結論先講」「講白一點」「有一件事要誠實說」黏著開場、「這正是 X 存在的理由」拔高收束 → 直接寫，去包裝殼
- **日期牆**（PR-080）：文章不逐日標行事曆日期（「07-14 接入、07-15 定界、07-16 翻案」式時間戳鏈是素材檔的事、不是文章的事）。敘事用相對時序（「接入當天」「隔天」「幾天後」）或直接省略；只有日期本身有意義的事件（發布日、版本釋出日）才標。判準：讀者不用記任何日期也能跟上因果。與「模糊時間/金額」條不衝突：時長／金額／數量照舊要具體，要拿掉的是行事曆日期。寫完 grep 日期樣式自查
- **蒸餾自創 label／AI 擬人詞**（PR-014）：抽象複合造詞硬塞正文（「被動硬牆」「暗系統」式＝看不懂）、「撐住它」式 AI 擬人當小標／金句 → 白話描述行為，名詞留 provenance
- **收尾又把整篇複述一次**（PR-088）：末段不重述前面已用案例證完的結論（exit-0-illusion 末節逐字複述前一節、連引號內句子都一樣；spec-review-round 收尾「三問也好，四層 Tier 也好，其實都不重要」把具體做法拉高成抽象迴圈）。收尾落在最後一個具體事實、真實態度句或下一步；前一節的自打臉本來就是更強的收尾。寫完把最後一段跟前面各節對讀，出現「講過的句子換句話說」就砍
- **替自己的段落封重要性**（PR-089）：不宣告這段有多重要（「這一段是全篇可信度的承重段」「這正是這篇的核心戲劇」「這是本篇的核心現場」＝大綱自評語沒清掉），讓內容自己說。與「拔高語」分工：那條管收束句拔高，這條管作者對自己段落打分。寫完 grep「這一段」「這正是這篇」「本篇最」「核心現場」「承重」
- **假洞見鉤子**（PR-090）：不用「這裡有個反直覺的點。」預告等一下有驚喜，直接給數字或對照。判準＝刪掉鉤子句後面自己站得住，那句就是廢句
