# Voice Profile - LINE Private Chat (v1)

## Caveat（必讀）

**這份 profile 是 register catalog，不是 blog writing template。**

不能直接拿 LINE voice 套 blog 草稿的三個理由：

1. **LINE 是 reply-chained 短句連發，blog 是思考成篇 long-form**。LINE 平均訊息 38 字（median）、p90 才 85 字、p99 142 字、max 317 字。一個論點通常拆 5-20 條 messages 連發。Blog 寫成「每段一句、爆量斷行」會像精神病
2. **LINE 對象是熟人群（布魯斯前端），blog 是 public reader**。LINE 出現的群內梗（人名、暱稱、群內事件）、髒話密度（幹 317 次 / 操 97 次 / 靠 96 次）、政治指控強度、性僻自爆（「分析個人性僻自動抓本」、「2TB 圖庫」、「打到破皮」）都是 **[群內限定]** 不能搬
3. **這份對照 v1 threads voice profile 用**——當你要 audit 自己 blog 草稿是不是「真實 voice」時，可以查 LINE 這邊的原始語料看「真的講話時會怎麼用這個詞」。例如 v1 寫「降智」標為 main #4 出處，LINE 這邊出現 12 次 + 「腦損」「降智的 X」變奏，能驗證這詞確實是 user 高頻語彙不是孤證

**正確用法**：寫 blog 想插入語助詞 / 比喻 / 諷刺收尾時，先查這邊有沒有真實例子，再決定要不要保留 register A（技術論述）的版本進 blog。**不要**把 register B（生活閒聊 / 群內梗 / 政治嘲諷）的語感直接搬

## Register 切分

LINE 訊息明顯切兩個 sub-register，混在同一群但語感差很大。

### Sub-register A: 技術論述

**特徵**：
- 連發 5-20 條 messages 講同一技術觀點（claude code skill / opus context window / vibe coding 攻擊手法 / 訂閱制 vs 點數制等）
- 帶具體數字（200K / 400K vs 600-700K / 15000 字元 / 25000 字元 / 7% / 4 小時 / 99 鎂）
- 工具擬人化（「opus 開始準備發瘋」「antigravity editor 本身 bug 很多」「gemini 大便」「claude 整天到晚掛掉」）
- 政治態度比 register B 收斂（談技術不太罵中共）
- 出現比例：估約 30-35%（1225 條提到 claude/gemini/codex 等模型，579 條提 vibe/skill/context/subagent/agent/cli/mcp/hook/prompt）

**代表例**（2026.04.21 連發 8 條談 skill description 上限）：
```
我最近反而在對 skill 做減法
claude code 這邊原本有一個隱藏的 skill description 預載入上限，15000 字元，但我瘦身前所有 skill 大概 25000 字元
也就是將近一半的 skill 永遠不會觸發，而且也不知道是哪一半
但我不知道你主力的 codex 會不會有這問題
```

**代表例**（2026.04.21 連發 4 條談 subagent + context）：
```
所以 superpowers 訂的 spec 其實都是給 main agent 看的，所有原則，怎麼拆 task 派發 subagent，怎麼 review 都是 main agent 在管
實測有沒有用 subagent 大概是 400K VS 600~700K context 差距
但我個人經驗，600K~800K 差不多是 opus 開始準備發瘋的臨界點
superpowers 剛推出的時代 ocntext 還只有 200K，有 subagent 的必要性吧
```

### Sub-register B: 生活閒聊 / 抬槓 / 群內梗

**特徵**：
- 短句嗆人 / 抬槓 / 接梗（吵架可連發 50+ 條）
- 髒話密度高（幹 / 操 / 靠 / 媽的）
- 政治直球（牆國 / 阿共 / 賴清德 / 妙天 / 海鯤號）
- 性 / 黃油 / 同人本 / 小黃油（「打到破皮」「2TB 圖庫」「沒寫過 NSFW」）
- 群內人名 @ 帶嘲諷（@fanli / @我不會 AI / @黃爸爸狗園）
- 出現比例：估約 60-65%
- **這 register 絕對不能搬進 blog**

**代表例**（2025.07.14 連發炒房抬槓）：
```
我以為的通膨:幹滷肉飯又漲 5 塊
偷偷把通膨的概念換成房價 XDDD
今天房價漲 100% 肯定也是抗通膨對吧
這啥左腳踩右腳的邏輯
```

**代表例**（2025.09.15 連發中共雙標自嘲）：
```
也不只雙標，現在台灣一堆問題害我沒辦法盡情嘲笑對岸
以前都會笑中國很會自慰，不管怎樣都是贏，現在台灣也一樣
```

## 句型 patterns

### A. 連發觀點串（最具代表 pattern）

**LINE 私聊本質就是「一個論點拆 5-20 條 messages 連發」**，不像 threads main 寫成 long-form。每條 5-50 字，連發完才換 topic。

**模板**：
```
觀點主句（一句斷論）
補充 1（具體例子 / 數字）
補充 2（補背景）
反駁假想對話（「但 ⋯⋯」「其實 ⋯⋯」）
收尾（雞湯反高潮 / 自貶 / 嘲諷）
```

**原文範例**（2025.07.14 16:10-16:14 連發 8 條談 AI 背鍋）：
```
但軟體業的 AI 目前全都是射後不理模式
也許未來連語言模型都要分背鍋等級
那就真的不需要人類了，就跟自駕還真不需要安全員一樣
有的還有一個花瓶安全員坐在駕駛座上，給後座的老闆一個安心感
像極了現在的我坐在工位上，唯一的作用就是給老闆安全感
但真的出事的時候花瓶不一定有能力處理，就像我現在系統出事了我也不一定看得懂 AI 的 code
```

**blog 套法**：把連發串「**重組成單段 long-form**」——保留論點順序，去掉換行，補連接詞。不要直接搬連發風進 blog。

### B. 一句斷論

**模板**：`X 就是 Y` / `X，差在 Z`

**例子**：
- 「**前端這種低門檻行業，入行大於一切**」
- 「**面試造火箭 工作擰螺絲**」
- 「**ai 刷題完全是船過水無痕，刷久了大腦都變光滑了**」
- 「**台灣民主政治最厲害的點就是每一任總統都能襯托前一任總統**」
- 「**真正作為產品基石的情況感覺還是 google 贏**」
- 「**現在的 AI 模型就是吃資料不想負責，吐回答也不想負責**」

**blog 套法**：threads main #4-5 模板的延伸，section 標題或段落首句直接用

### C. 比喻教學

**頻率**：109 次「就像 / 跟⋯一樣 / 彷彿 / 像極了」。比 v1 threads（main 17 篇估約 5-8 次）密度更高，但 LINE 是即興比喻，常帶髒話 / 性 / 政治。

**原文範例**：
- 「**一直在重複問 AI 會不會取代工程師就跟去年的海哥一直問 React 還是 Vue 好一樣，永遠門口蹭蹭不進去**」
- 「**就跟我的 code 一樣，寫了 A??B，A 爛成一坨屎我也不在乎**」
- 「**像極了現在的我坐在工位上，唯一的作用就是給老闆安全感**」
- 「**就是會有這種人，開在馬路上逆向會說是所有人都在逆向**」
- 「**簡直就像 1980 穿越來的日本人**」
- 「**台灣永遠有 fallback 方案，跟爸爸買，就這樣還想自己搞喔**」

**blog 套法**：核心 marker，threads 已驗證可用（「庫塔貝拉」「張飛打岳飛」），blog 段落收尾或論點解釋時插入

### D. 自我糾錯星號

`*正確字` pattern，重發訊息修上一則錯字。

**例**：「MAX 有記憶體魔術」→ 「*MAC」/「沒有下午場 純放淚時間」→ 「*浪費」

**blog 套法**：blog 是寫完才發，不適用——但可以**模擬**自我修正寫法（「不對，其實是 X」「更正：Y」），threads main #10 自問自答有類似結構

### E. 自問自答 + 結論

**例**（2025.05.13）：
```
拜託想討論這個議題的請自己去試就知道了，大家都是工程師應該有自己一套評斷方法，除非你不是工程師是網軍
這樣討論時就能聊 AI 使用心得或是踩坑抱怨，而不是每次都在問 AI 會不會取代工程師，然後另一個人再去問 AI 你會不會取代工程師
```

**blog 套法**：呼應 threads main #9-10 自問自答模板，blog 可用

## Emoji / 表情符號使用

**LINE 上 emoji 密度極低**，跟 threads 差很大。

| Emoji | 次數 | 用法 | 對照 v1 threads |
|---|---|---|---|
| 🤣 | 7 | 諷刺 / 自嘲 | threads 30+ 次「最高頻」，LINE 只用 7 次 |
| 🤔 | 10 | 真好奇 / 半開玩笑 | 跟 threads 相近 |
| 😭 | 1 | 委屈 | threads 用更多 |
| 🤪 / ☺ / 🥲 / 😂 / 😇 / 🥹 / 😅 / 😀 | 各 0-2 | — | threads 都有，LINE 幾乎不用 |
| XD | 81 | 文字 emoji | LINE 主力，threads 少 |
| 484 | 23 | PTT「是不是」諧音 | **[群內限定]** |
| = = / .. / @@ | 36 / 散見 / 散見 | 文字表情 | LINE 私聊用 |
| 👾 / 😡 / 🐒 | 散見 | 即興 | 不通用 |
| 「圖片」（純文字 placeholder） | 18 次 | LINE 匯出時把 sticker/gif 通通變「圖片」二字 | LINE-only artifact |

**對照發現**：
- v1 threads 寫「🤣 是核心 marker」高頻使用 → LINE 反而很少用 🤣
- LINE 主力文字 emoji 是 **XD（81 次）**和 **484（23 次）**，這兩個 threads 幾乎不用
- 推斷：threads 是「公開呈現嘲諷」需要 🤣 visual marker；LINE 是「私下嘴砲」用 XD / 484 / 文字直接吐槽就夠

**blog 套法**：照 v1 threads 用 🤣 為主，不要學 LINE 的 XD / 484

## Anti-pattern（用 LINE voice 寫 blog 會壞的點）

| 「幹 我發現這個對話紀錄改名會溯及既往」（2026.03.19）開頭 | 髒話發語 + 即時反應，blog 不是即時反應 | 改「最近發現 LINE 對話紀錄改名會溯及既往」 |
| 「opus 600-800K 差不多是 opus 開始準備發瘋的臨界點」+ 連發 | blog 寫成這樣會像精神病爆量斷行 | 重組成單段：「我自己 600K-800K context 大概是 opus 開始發瘋的臨界點，這時候塞 subagent 才開始划算」 |

### Anti-pattern 補充：比喻教學 marker 不可直接 patch acceptable draft（2026-05-17 v5.1 實驗 verified）

從 acceptable baseline v5-self-zh 注入 5 個 LINE register A marker 產 v5.1，user verdict「整體看起來沒有比較好，新增的小故事都有點尷尬」。檔案保留為 `posts/draft-retire-vector-memory-v5.1-line-enhanced.md` 當 anti-pattern reference。

5 處 patch 全部 mismatch：
1. 「跟把整本筆記本影印件全部塞進搜尋框沒兩樣」← 比喻教學移植，搬到 blog 變說教感
2. 「向量吃力不討好，連到底要撈關鍵字還是撈意境都不知道」← 取代 v5「找不到就業機會」原句更狠 + 更精煉
3. 「現成的菜不吃，在那邊研究新鍋具」← 生活比喻太親民，跟周圍技術論述 register 不協調
4. 「我自己」→「我這邊」← LINE 83 次核心 marker，但 v5 結尾已有「我這邊」=用太多次失去 marker 強度
5. 「反正讀寫比 0.09% 這事我這邊已經幫你試過了」← 自指反差語感過熟，跟原本「省下蓋向量資料庫那兩個下午」克制 tone 衝突

**修正前面 takeaway #5**：
- ~~比喻教學是 LINE 比 threads 更密集的 marker：blog 可以多放比喻句~~
- **修正版**：比喻教學在 LINE 是 109 次高頻 marker，但**不可拿來 patch 已 acceptable 的 blog draft**。LINE 比喻多半服務「即時回應對方 query 的解釋需求」（教學 register），blog 是「成文論述」不需即時解釋——同一段比喻在 LINE 是降低門檻，在 blog 是說教/拖節奏。比喻在 blog 只能**在 draft 設計階段 organically 長出來**，不能事後注入

**通則**：LINE marker 是 **validation 用 不是 injection 用**。看到 marker 在 LINE 高頻不等於 blog 該補；只能用來確認「user blog 自然寫出來的 X 確實是真實 voice」。

## 給 blog 寫作的具體 takeaway

1. **register A 技術論述 → blog 主軸**。LINE 上連發的技術觀點重組成段落直接可進 blog（補連接詞、去髒話發語、保留量化證據 / 擬人化動詞）
2. **register B 生活閒聊 → 砍 90%**。只保留「比喻教學」「自貶反差」「雞湯反高潮」這三個元素可進 blog，其他全砍
3. **LINE 真實高頻語彙跟 threads 一致的部分**（蹭 / 韭菜 / 肥宅 / 帥潮 / 魯蛇 / 社畜 / 降智 / 爛 / 翻車 / 過氣 / 笑死 / 這邊 / vibe / 調教）：放心進 blog
4. **LINE 才有 threads 沒的元素**（XD / 484 / = = / 文字 emoticon / @ 互動 / 群內梗）：絕對不進 blog
5. **比喻教學是 LINE 比 threads 更密集的 marker**（109 次 vs threads main 估 5-8 次）：blog 可以多放比喻句，這是 user 真實口語特徵
6. **emoji 反向校正**：blog 跟 threads 一致用 🤣（核心 marker），不要學 LINE 的低密度 emoji + 文字 emoticon

## Pending（蒸不出來的軸）

1. **「lead 開場」分類精確度有限**：LINE 是即時 reply 沒有「正式 lead」的概念，所以 LINE 蒸出的開場 pattern（幹 / 欸 / 對啊 / 哎）跟 blog 的 lead 是不同 grammar 結構，**不能直接用 LINE 樣本驗證 blog 的 lead 選擇**。Insufficient sample to map LINE openers to blog leads
2. **「文章長度」這軸不適用**：LINE 沒有「文章」的概念，無法蒸 blog 長度建議。沿用 v1 threads 800-1500 字結論
3. **「Series / thread 結尾」這軸不適用**：LINE 不寫 series，沒有「2/2 收尾」這種結構
4. **完整 long-form 論述的範例極少**：14,642 條 LINE 訊息中，p99 才 142 字，**幾乎沒有 long-form 樣本**。意思是「user 在 LINE 上不會練 long-form」——這也意味 blog long-form 的 voice 校準**主要還是要靠 threads main 17 篇**，LINE 只能驗證局部 voice marker
5. **「對人 vs 對事比例」這軸 LINE register B 嚴重偏「對人」**（吵架 / 抬槓佔大量），不能類推 blog。Insufficient context — blog 必須是 100% 對事
