## 句型 patterns（高度可複製）

### Long-form 模板（main 出現多次）

#### 1. 省流排序 + 分項解釋（main #4-5）
```
省流: A >> B >= C > D > E
分項心得：
1. A: <spec> + <擬人化評> + 缺點 + 適合場景
2. B: ...
```

#### 2. 條列回顧（main #16 面試, #17 live coding）
```
標題 + 引入句（最近 X / 剛好看到 Y）
Day0: ...
Day3: ...
（或）
1. <題型>：<描述> + <個人經驗>
2. ...
隨手小記，有機會再寫成一篇 medium
```

#### 3. 自問自答（main #9 → #10 m5 macbook）
```
問題篇：求救 / 求情報
答題篇：「**這邊自問自答**」+ 實測結果 + 「**供大家參考**」
```

#### 4. 故事敘述 + takeaway（main #15 ADHD）
```
場景描述（給 AI 指令-等-滑手機-切回 review）
個人感悟（甚至把吃十幾年的利他能戒掉）
```

### 高頻句型（main + replies 都見）

- **「省流：X >> Y >= Z > W > V」** — 開頭直接排序
- **「能力相當於 X，講白話就是 Y」** — 術語自帶轉譯
- **「重點是 ⋯⋯ 反觀 ⋯⋯」** — 對比結構
- **「就是 ⋯⋯ 而已，差在 ⋯⋯」** — 收斂判斷（reply 高頻：「cowork 就是對 claude code 的包裝**而已**，差在沒有友善的圖形化操作介面」）
- **「也算是老問題了」** — 雲淡風輕收尾
- **「沒想到 ⋯⋯」** — 開場驚訝
- **「終究是 ⋯⋯」** — 結論型修飾
- **「在我這實在找不到就業機會」** — 擬人化收尾
- **「選自己喜歡的就好」** — 放手式建議結尾
- **「這邊自問自答」** — 跟自己對話（v0 漏）
- **「這邊不確定 ⋯⋯ / 這邊推薦 ⋯⋯」** — 第一人稱位置感
- **「就趁連假 vibe 了一個 X」** — 動詞化 vibe / 工具 / 名詞當動詞
- **「幻覺蒸餾🤣」** — 兩字濃縮諷刺
- **「庫塔貝拉」「張飛打岳飛」** — 引典型比喻（「**claude code 對標的是 codex，你這樣比屬實是張飛打岳飛了**」）

## 文章長度

- **Threads main**：
  - 短哲學 / 觀察句：1-3 行（main #11 / #13 / #14 / #15）
  - 中等敘事：5-15 行（main #6 / #7 / #15 / #16）
  - 長條列 / 評比：拆 1/2, 2/2（main #2-3 mimo, #4-5 模型評比, #9-10 m5）
- **Replies**：5-100 字為主，極少超過 200 字（吵架時例外，#670 / #671 / #20）
- **Blog 推估**：
  - **800-1500 字 = 舒適區**（介於 main long-form #4-5 的兩篇加總 + #16 面試紀錄 + #17 live coding 之間）
  - **2000+ 要拆 series**（threads 已驗證「拆 1/2 + 2/2」的習慣）
  - 別硬撐到 3000+ — 1500 後資訊密度會降，違反「省流」精神

## Anti-pattern（**不要這樣寫**）

- 「在這個 AI 快速演進的時代⋯⋯」LLM 廢開場
- 「綜上所述」「值得注意的是」「不僅 ... 而且 ...」「然而 ...」教科書語氣
- 過度修飾形容詞「驚人地」「令人印象深刻」「優雅地」「極為強大」「顯著提升」
- 客觀化第三人稱「在使用者經驗中發現」「本文將探討」「筆者認為」
- 「請參考」「歡迎指教」「希望本文對您有所幫助」文件式邀請
- 全段 emoji 像 LinkedIn 文
- 用「我們」當主詞（除非真有對話對象）
- 用「個人化」「賦能」「賦予」「打造」「閉環」「玩法」這類 PR 術語
- 用「✅ ❌ ⚠️」式工具 emoji 當條列 marker
- 假對話「你可能會問：那 X 怎麼辦？」（user 不喜歡這種偽蘇格拉底）
- **「不是 X，是 Y」對偶排比（GPT 招牌句式）**：忌「不是 A，是 B」「不是 A，而是 B」「真正的 X 不是…是…」這種工整對偶，**尤忌一篇 ≥2 次同構**（讀者秒認的農場 AI tell；keep-the-wiki-alive 發佈版一篇中 6 次被外部讀者點名）。要下判斷就直接講——threads 慣用「就是…而已，差在…」「重點是…反觀…」「X？廢話，誰不會講」，對比靠語氣不靠排比骨架
- **破折號（——）每篇上限 1-2，預設不用**（PR-016/021）：人類技術寫作極少用破折號，連續拿「——」當轉折或插入是 AI 節奏 tell（code-search-adoption Phase 2 一篇冒 25 個、上線收到 2；memory-cap-reframe 也冒 8）。預設改用句號斷句、冒號帶出、逗號或括號插入；標題一律不用破折號。寫完 grep `——` 計數，超過 2 就重整標點
- **AI 儀式性過渡 / 拔高語**：「結論先講：」「講白一點：」「有一件事要誠實說：」開場黏著詞、「這正是 X 存在的理由」「這就是它的意義所在」式收束拔高——直接寫，不要這層 LLM 包裝殼
- **蒸餾自創複合 label／AI 擬人詞**（PR-014）：蒸餾造的抽象複合名詞硬塞正文（「被動硬牆」「暗系統」式——讀者甚至作者本人會「看不懂、怪詞」）；「撐住它」式 AI 擬人或抽象動詞當小標／金句。一律白話描述行為，自創名詞留 provenance 不入文

## Cross-check 反向萃取（CLAUDE.md / memory）
